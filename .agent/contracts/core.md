# Core execution contract

Use current source, configuration, schemas, manifests and tests for technical
truth; current Git/GitHub for work state; current runtime observations for live
claims; accepted governance/decisions for policy. Historical reports are context.
Reconcile conflicting evidence by data type rather than calling every source equal.

Inspect the relevant files and instructions proportionately before changing them.
State the requested outcome and acceptance conditions. Preserve architecture,
terminology and design choices unless the task needs a justified change.
Preserve unrelated dirty/untracked/concurrent work; narrow edits and staging to
task-owned paths. Do not reset, stash, clean or overwrite someone else's work.
Isolate work when overlap makes safe editing uncertain.

Keep dependency changes necessary, reviewable and compatible with native tooling.
Do not replace a missing runtime with an unapproved substitute. Record unavailable
verification honestly. Repair causal defects, not check results or evidence.
Treat follow-ups as steering unless they change the objective. Record adjacent
work separately; do not silently implement it. Never fabricate access or results.
